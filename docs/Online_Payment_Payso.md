# รับชำระเงินออนไลน์ (สแกน QR แบบเดิม + บัตรเครดิตผ่าน Payso)

## สรุปสั้น

ลูกค้าเลือกได้ว่าจะ **สแกน QR โอนแล้วแนบสลิป (แบบเดิม)** หรือ **จ่ายด้วยบัตรเครดิต/QR
ตัดยอดอัตโนมัติผ่านเกตเวย์** ตั้งค่าได้ทุกส่วนจากหน้าเว็บ

> **ปิดสวิตช์แล้วระบบทำงานเหมือนเดิมทุกอย่าง** — ค่าเริ่มต้นคือ *ปิด* ทั้งใน `Feature.DefaultOff`
> และในตาราง ⇒ deploy แล้วยังไม่มีอะไรเปลี่ยนจนกว่าจะเปิดเอง

---

## ⚠ ข้อจำกัดที่ต้องรู้ก่อนใช้งานจริง — สัญญา API ของ Payso

**เครื่องที่พัฒนาเข้า `https://api-docs.payso.co` ไม่ได้** (ถูกบล็อกที่ proxy ของสภาพแวดล้อม —
ทั้ง WebFetch และ `curl` ได้ `CONNECT tunnel failed, response 403`) และค้นหาจากที่อื่นก็ไม่พบ
เอกสารสาธารณะของ Payso

ตามกฎของโครงการ (**"ห้ามเดา"** — ยิ่งเป็นเรื่องเงินยิ่งเดาไม่ได้) จึง **ไม่ได้ hard-code
สัญญา API ลงในโค้ด** แต่ทำให้ทุกอย่างเป็น **ค่าตั้งค่าที่แก้จากหน้าเว็บได้ทันที ไม่ต้อง build ใหม่**:

| สิ่งที่ต้องตรงกับเอกสารจริง | แก้ได้ที่ (ศูนย์ตั้งค่า → รับชำระเงินออนไลน์) |
|---|---|
| Base URL (sandbox / production) | `Payso_BaseUrl_Sandbox`, `Payso_BaseUrl_Production` |
| วิธีส่งกุญแจ (Bearer / หัวข้อเฉพาะ) | `Payso_Auth_Mode`, `Payso_ApiKey_Header`, `Payso_Extra_Headers` |
| ลายเซ็นคำขอ | `Payso_Signature_Header`, `Payso_Signature_Algo`, `Payso_Signature_Encoding` |
| เส้นทาง endpoint | `Payso_Path_CreatePayment`, `Payso_Path_QueryPayment`, `Payso_Path_Refund` |
| **รูปคำขอ (JSON)** | `Payso_Request_Template` — ใส่ตัวแปร `{{ref}}` `{{amount}}` ฯลฯ |
| ชื่อวิธีชำระฝั่ง Payso | `Payso_Method_Map` |
| **ตำแหน่งฟิลด์ในคำตอบ** | `Payso_Response_Map` (ใส่ได้หลายทางเลือก ระบบลองไล่จนเจอ) |
| คำที่แปลว่า จ่ายแล้ว/รอ/ไม่สำเร็จ | `Payso_Status_Paid`, `_Pending`, `_Failed` |
| ลายเซ็นของ webhook | `Payso_Webhook_Sig_Header`, `Payso_Webhook_Secret`, `Payso_Webhook_Verify` |

ค่าที่ใส่ไว้ตอนนี้เป็น **ค่าตั้งต้นทั่วไปของเกตเวย์ไทย ไม่ใช่สัญญาจริงของ Payso** — ต้องเทียบ
เอกสารแล้วแก้ก่อนเปิดใช้งานจริง

**ทางลัดในการปรับให้ตรง:** กดปุ่ม **🔌 ทดสอบการเชื่อมต่อ** ในหน้าตั้งค่า → ระบบยิงคำขอจริง
ยอด 1 บาท แล้วแสดง **คำขอที่ส่งไป + คำตอบที่ได้แบบดิบ ๆ** ใช้คำตอบนั้นปรับ `Payso_Response_Map`
ให้ตรงได้เลย

## สิ่งที่ติดตั้ง

### ฐานข้อมูล — `Database/PHASE19_Migration_05_Online_Payment.sql`
| ตาราง | ใช้ทำอะไร |
|---|---|
| `Payment_Gateway_Config` | ค่าตั้งทั้งหมด (ค่าลับเก็บแบบเข้ารหัส) |
| `Payment_Transaction` | รายการชำระเงิน + สถานะ + คำขอ/คำตอบดิบ |
| `Payment_Transaction_Event` | ข้อความที่เกตเวย์แจ้งกลับ (ดิบ) — unique บน `Provider+Event_ID` กันทำซ้ำ |

เพิ่มสวิตช์ `Feature_OnlinePayment` (ปิด) และโมดูลสิทธิ์ `SYS_PAYMENT`
(ให้กลุ่มที่มี `SYS_ACCOUNTING` อยู่แล้วอัตโนมัติ — ไม่มีใครเสียสิทธิ์)

### โค้ด — `Take Time BangPhra/Class/Payments/`
| ไฟล์ | หน้าที่ |
|---|---|
| `PaymentGatewayConfig` | อ่าน/เขียนค่าตั้ง (cache 30 วิ) + ตัดสินว่าวิธีไหนแสดงให้ลูกค้าเห็น |
| `IPaymentGateway` | สัญญาของเกตเวย์ — เพิ่มเจ้าอื่นได้โดยไม่แตะหน้าจอ |
| `PaysoGateway` | ตัวเชื่อม Payso (รายละเอียด HTTP ทั้งหมดมาจากค่าตั้ง) |
| `PaymentTransactionStore` | อ่าน/เขียนรายการ + กันจ่ายซ้ำ/บันทึกซ้ำ |
| `OnlinePaymentService` | สมองของระบบ — เริ่มจ่าย / รับ webhook / ตามสถานะ / ลงบันทึกเข้าระบบเดิม |

### หน้าจอ
| หน้า | ใคร |
|---|---|
| `Payment/Pay.aspx` | ลูกค้า — เลือกวิธีชำระแล้วจ่าย |
| `Payment/PayResult.aspx` | ลูกค้า — หน้ากลับหลังจ่าย (ถามสถานะจริงจากเกตเวย์เสมอ) |
| `API/PaymentWebhook.ashx` | เกตเวย์ — แจ้งผลการจ่ายกลับมา |
| `Admin/Settings/PaymentGateway.aspx` | ผู้ดูแล — ตั้งค่าทุกอย่าง + ทดสอบ + ดูรายการ |

## ขั้นตอนเปิดใช้งาน

1. รัน `Database/PHASE19_Migration_05_Online_Payment.sql`
2. build + deploy (ต้องทำบน Windows + IIS)
3. **ตั้งค่า QR แบบเดิมก่อน** — ศูนย์ตั้งค่า → รับชำระเงินออนไลน์ → หมวด *สแกน QR แบบเดิม*
   (รูป QR ของร้าน + ข้อมูลบัญชี) แล้วเปิด `Payment_Enabled`
   *ถึงตรงนี้ยังไม่ต้องมี Payso ก็ใช้ได้แล้ว — ลูกค้าจ่ายด้วยการโอน+แนบสลิปผ่านหน้าเดียว*
4. เปิดสวิตช์ `Feature_OnlinePayment` ที่ ศูนย์ตั้งค่า → ตั้งค่าระบบ → หมวด "ฟีเจอร์"
5. **ถ้าจะใช้บัตรเครดิต:** ใส่ค่า Payso จากเอกสารจริง → โหมด `SANDBOX` → กด **ทดสอบการเชื่อมต่อ**
   → ปรับ `Payso_Response_Map` ตามคำตอบที่ได้ → ทดสอบจ่ายจริงใน sandbox
6. นำ **Webhook URL** (แสดงอยู่บนสุดของหน้าตั้งค่า) ไปใส่ในระบบ Merchant ของ Payso
7. ใส่ `Payso_Webhook_Secret` + เปิด `Payso_Webhook_Verify` → ทดสอบว่าจ่ายแล้วสถานะเปลี่ยนเอง
8. เปลี่ยนเป็น `PRODUCTION` แล้วเพิ่ม `CARD` เข้า `Payment_Methods_Enabled`

> ถ้าเว็บอยู่หลัง proxy/CDN **ต้องใส่ `Payment_Site_BaseUrl`** ไม่งั้น Webhook/Return URL
> ที่ส่งให้เกตเวย์จะเป็นที่อยู่ภายในและเกตเวย์เรียกกลับไม่ได้

## กติกาความปลอดภัย/ความถูกต้องที่ระบบยึด

1. **จ่ายซ้ำไม่ได้** — `UPDATE … WHERE Status <> 'PAID'` เปลี่ยนได้ครั้งเดียว
2. **ลงบันทึกซ้ำไม่ได้** — จองสิทธิ์ด้วย `Applied_At`; ถ้าลงไม่สำเร็จจะคืนสิทธิ์ให้รอบถัดไปลองใหม่
3. **webhook ซ้ำไม่ทำงานซ้ำ** — unique index `Provider + Event_ID`
4. **ตรวจลายเซ็นก่อนเสมอ** — ไม่ผ่าน = 401 ไม่แตะข้อมูล (เทียบแบบ fixed-time)
5. **ตรวจยอด** — เกตเวย์ต้องแจ้งยอดตรงกับที่เราขอ ไม่งั้นไม่บันทึกว่าจ่ายแล้ว
6. **สถานะที่ไม่รู้จัก = ยังไม่จ่าย** ไม่เดาไปทางบวก
7. **หน้ากลับ (Return URL) ไม่ใช่หลักฐาน** — ระบบไปถามเกตเวย์จริงทุกครั้ง
8. **แก้ยอดใน URL ไม่ได้** — ยอดที่เรียกเก็บคำนวณจากฐานข้อมูล ลิงก์ระบุได้แค่ "ไม่เกินยอดค้าง"
9. **ยอดที่ลงบัญชีคือยอดรายการจริง** — ค่าธรรมเนียมบัตรที่บวกให้ลูกค้าแยกไว้ที่ `Surcharge_Amount`
10. **เก็บดิบทุกครั้ง** — `Raw_Request` / `Raw_Response` / `Raw_Body` ตรวจย้อนหลังได้เสมอ
11. **webhook หายก็ไม่ตกหล่น** — งานเบื้องหลังใน `Global.asax` ตามสถานะรายการที่ค้าง
    และปิดรายการที่หมดอายุให้เอง

## สิ่งที่ยังไม่ได้ทำ (ตั้งใจ)

- **ยังไม่รับข้อมูลบัตรบนเว็บเรา** — ใช้หน้าชำระเงินของผู้ให้บริการ (hosted page) เท่านั้น
  เพื่อไม่ให้ข้อมูลบัตรผ่านเซิร์ฟเวอร์เรา (ลดภาระ PCI-DSS ลงมาก)
- **ยังไม่ผูกกับรูมเซอร์วิส / เบิกของใช้** — หน้า `Pay.aspx` รองรับ `RESERVATION` และ `ACTIVITY`
  เพิ่มชนิดอื่นได้โดยเติมเคสใน `LoadSource` + `ApplyPaid`
- **ยังไม่ยิงเข้า NextAcc โดยตรง** — ฝั่งค่าที่พักไปตามเส้นทางเดิม (`ProcessAdditionalPayment`)
  จึงได้ใบเสร็จ/การลงบัญชีเหมือนพนักงานคีย์เอง; ฝั่งกิจกรรมยังเป็นการอัปเดตสถานะเท่านั้น (เหมือนเดิม)
- **ปุ่มคืนเงินยังไม่มีในหน้าจอ** — โค้ด `Refund()` พร้อมแล้ว รอเส้นทางจริงจากเอกสาร

## ยังต้องทำ

- [ ] เอาเอกสาร Payso จริงมาเทียบ แล้วแก้ค่าในหน้าตั้งค่าให้ตรง
- [ ] build บน Windows (สภาพแวดล้อมนี้ build WebForms ไม่ได้)
- [ ] ทดสอบ sandbox ครบวง: สร้างรายการ → จ่าย → webhook → สถานะเปลี่ยน → ใบเสร็จออก
