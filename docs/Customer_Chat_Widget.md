# แชทลูกค้าทั่วไป (หน้าเว็บ + LINE/Facebook/TikTok) + จองผ่านแชท

## ภาพรวม

ลูกค้ากดไอคอนแชทลอยมุมขวาล่างของทุกหน้าเว็บสาธารณะ → ถามห้องว่าง/ราคา/จองได้เลย โดยไม่ต้องล็อกอิน
ใช้สมอง AI ที่มีอยู่แล้ว (`AIKnowledgeService.ProcessAutoReply`) ซึ่งทำงานเป็นลำดับ:

```
คำถามลูกค้า
   │
   ├─ 1. Knowledge Base (ค้นก่อน — เร็ว/ฟรี, ตอบตรงถ้ามั่นใจ ≥ 50%)
   │
   ├─ 2. DeepSeek AI (ถ้า KB ไม่เจอ) — ใช้ System Prompt + สไตล์ที่ป้อนสอนไว้
   │       + แนบข้อมูลห้องว่าง/ราคา (BOOKING_LOOKUP)
   │
   └─ 3. สร้างการจอง (BOOKING_CREATE) — AI เก็บข้อมูลครบ → ออกคำสั่ง {{BOOK:…}}
           → สร้าง Reservation สถานะ "รอยืนยัน"
```

**ช่องทางเดียวกันทำงานทั้ง หน้าเว็บ / LINE / Facebook / TikTok** — ทุกข้อความเข้ากล่องแชทรวม
(OmniChannel Inbox) พนักงานเห็นและรับช่วงต่อได้ทุกช่องทาง

## เปิดใช้งาน

1. **รัน migration** `PHASE18_Migration_22_WebChat_TikTok.sql` (เพิ่มช่องทาง WEBCHAT + TIKTOK)
2. **เปิด AI**: Admin → ตั้งค่า → AI Settings — ใส่ DeepSeek API Key + เปิด `AI_Enabled`
3. **เปิดฟีเจอร์แชท**: Admin → AI Knowledge Base → เปิดสวิตช์ที่ต้องการ:
   - `AUTO_REPLY` — ตอบอัตโนมัติ (จำเป็น)
   - `BOOKING_LOOKUP` — ให้ค้นห้องว่าง/ราคา
   - `BOOKING_CREATE` — ให้สร้างการจอง (รอพนักงานยืนยัน)
   - `AUTO_REPLY_KB_ONLY` — (ออปชั่น) ตอบเฉพาะจาก KB ไม่เรียก AI เสียเงิน
4. **แชทหน้าเว็บ**: Admin → ตั้งค่าช่องทาง → เปิด **แชทหน้าเว็บ (WEBCHAT)**
   → ไอคอนแชทลอยจะโผล่บนหน้าเว็บทันที (เห็นเฉพาะผู้เยี่ยมชม ไม่เห็นตอนพนักงานล็อกอิน)

## สอน AI ให้ตอบตรงสไตล์

- **Knowledge Base** (Admin → AI Knowledge Base): เพิ่มคำถาม-คำตอบเอง หรือ import จากไฟล์/CSV
  → คำตอบเหล่านี้ถูกใช้ก่อนเสมอ (แม่นและฟรี)
- **เรียนจากพนักงาน**: เมื่อพนักงานตอบลูกค้าในกล่องแชท ระบบเก็บเป็นตัวอย่าง (`LearnFromStaffReply`)
  → AI นำสไตล์/คำตอบไปใช้ครั้งต่อไป
- **System Prompt** (AI Settings): กำหนดบุคลิก/น้ำเสียง/ข้อมูลหลักของที่พัก

## ขั้นตอนจองผ่านแชท (ครบวงจรเหมือนคนทำจริง)

1. ลูกค้าถาม "มีห้องว่าง 15-17 มิย. ไหม" → AI เช็คห้องว่าง + เสนอราคา
2. ลูกค้าตกลง + ให้ชื่อ/เบอร์ → AI สร้าง **การจองสถานะ "รอยืนยัน"** + โชว์การ์ดสรุป + ปุ่ม **"แนบสลิปโอนเงิน"**
3. ลูกค้าแนบสลิป → เก็บไฟล์ + ลงรูปในกล่องแชท + **แจ้งพนักงานทาง Telegram**
4. พนักงานตรวจสลิป → กดยืนยันในกล่องแชท/หน้าจองรอยืนยัน (`ConfirmBookingByStaff`)
   → สถานะเป็น "ยืนยันแล้ว" → แจ้งผลกลับลูกค้าทางแชท

**ทำไมต้องรอพนักงานยืนยัน:** การจองจากแชทมาจากข้อความลูกค้า (untrusted) + ต้องตรวจสลิปจริง
จึงตั้งเป็น "รอยืนยัน" เสมอ (มี guardrails: ตรวจเบอร์/วันที่/จำนวนคน + จำกัดจำนวนจองค้างต่อเบอร์/บทสนทนา)

## TikTok

- **ขาเข้า**: ตั้ง Webhook ของ TikTok ให้ยิงมาที่ `…/API/OmniChannelWebhook.ashx?channel=TIKTOK`
  (รับ JSON: senderId / senderName / message / messageId) → เข้ากล่องแชท + auto-reply เหมือนช่องอื่น
- **ขาออก**: TikTok DM API ยังจำกัดสิทธิ์ (ต้องได้รับอนุมัติ scope + business account)
  → ตั้ง `accessToken` + `sendUrl` ในหน้าตั้งค่าช่องทาง TikTok; ถ้ายังไม่ได้สิทธิ์ ตอบผ่านแอป TikTok ได้
  (ข้อความเข้ากล่องแชทครบ)

## ปุ่ม 💬 แชทลูกค้า ในตารางผู้เข้าพักรายวัน

ลูกค้าที่**จองแล้ว**และทักเข้ามาทางช่องทางใดก็ตาม จะขึ้นปุ่มแชทที่แถวการจองนั้นในหน้า
**ผู้เข้าพักรายวัน** — กดแล้วเปิดบทสนทนาของลูกค้าคนนั้นทันที

- ปุ่มบอก**ช่องทางที่ลูกค้าติดต่อมา**: `💬 LINE` · `💬 Facebook` · `💬 TikTok` ·
  `💬 อีเมล OTA` · `💬 แชทเว็บ` (ถ้าทักหลายช่องทาง แสดงอันที่มีข้อความล่าสุด)
- ยังมีข้อความ**ยังไม่อ่าน** → ปุ่มเป็น**สีแดง**พร้อมตัวเลข เช่น `💬 LINE (3)`

### ระบบรู้ได้ยังไงว่าใครคือการจองไหน — `ChatBookingLinker`
จับคู่อัตโนมัติทุกครั้งที่ลูกค้าส่งข้อความ (ทำงานก่อนเช็คสวิตช์บอท จึงผูกให้แม้ปิด AI)
เรียงตามความน่าเชื่อถือ:

1. **การจองที่เกิดในแชทนี้เอง** (`AI_Booking_Actions.ConversationID`) — แน่นอนที่สุด, ผูกทันทีที่จองสำเร็จ
2. **เบอร์โทรที่ลูกค้าพิมพ์** (รองรับ `0812345678`, `081-234-5678`, `+66812345678`) → หาการจองของเบอร์นั้น
3. **เลขการจอง / เลข Booking ของ OTA** ที่ลูกค้าพิมพ์ (เช่น "จอง 1234", "booking 2038656748")
4. **เบอร์ที่ผูกกับ contact ไว้แล้ว** (เช่น WhatsApp ที่ platform id คือเบอร์)

ผูกเฉพาะการจองที่**ยังไม่ยกเลิก** และยัง**ไม่เลยเช็คเอาท์เกิน 14 วัน** (เผื่อลูกค้าทักหลังกลับ เช่น ลืมของ)
ผูกแล้วจะไม่เขียนทับ และระบบเติม**ชื่อลูกค้าจริง**ให้ contact ด้วย (กล่องแชทจะโชว์ชื่อคน ไม่ใช่รหัส platform)

**ถ้ายังจับคู่ไม่ได้:** ลูกค้า LINE/FB ที่ยังไม่เคยบอกเบอร์หรือเลขจอง ระบบจะยังไม่รู้ว่าเป็นใคร
— พนักงานถามเบอร์ในแชทครั้งเดียว ระบบจะผูกให้เองทันทีจากข้อความนั้น

## ความปลอดภัย / ข้อจำกัด

- ตัวตนลูกค้า = `sid` สุ่มฝั่ง client (ไม่มีข้อมูลส่วนตัว) → `PlatformUserId = web_{sid}`
- แนบสลิป: ตรวจนามสกุล + สร้างชื่อไฟล์เอง (ผ่าน `UploadHelper` — กัน web shell) + ผูกกับเลขจองของ sid นั้นเท่านั้น
- endpoint สาธารณะ `API/PublicChat.ashx` — จำกัดความยาวข้อความ, การจองมี rate-limit ในตัว
- ถ้า AI ปิด/ไม่มั่นใจ: ตอบว่า "พนักงานจะติดต่อกลับ" และข้อความยังอยู่ในกล่องแชทให้พนักงานตอบเอง
