# กลุ่มสิทธิ์ (Permission Groups)

## ปัญหาเดิม

| ปัญหา | รายละเอียด |
|---|---|
| สิทธิ์ตายตัว 3 แบบ | มีแค่ `Owner` / `Admin` / `Staff` เก็บใน `Admin.Role` — เพิ่มกลุ่มเองไม่ได้ |
| เปิด-ปิดรายส่วนไม่ได้ | อยากให้แม่บ้านเห็นเฉพาะงานแม่บ้าน หรือให้บัญชีเห็นเฉพาะการเงิน — ทำไม่ได้ |
| เช็คสิทธิ์กระจาย | มีการเทียบ `Session["User"] == "Owner"` ฝังอยู่ **54 หน้า** แก้ทีต้องไล่ทุกไฟล์ |
| Staff เห็นมากเกิน | พนักงานหน้าร้านเห็นเมนูใบเสร็จ ใบสำคัญจ่าย ข้อมูลลูกค้า เท่ากับ Admin |

## ของใหม่

**Admin → ตั้งค่า → กลุ่มสิทธิ์ผู้ใช้** (Owner เท่านั้น)

- **สร้างกลุ่มเองได้ไม่จำกัด** เช่น "แม่บ้าน", "บัญชี", "ฟรอนต์กะดึก"
- กำหนดต่อส่วนงาน **25 โมดูล** ได้ 2 ระดับ:
  - 👁 **มองเห็น** — เมนูขึ้นหรือไม่
  - 🔓 **เข้าใช้งาน** — เปิดหน้านั้นได้หรือไม่ (ติ๊กแล้วจะติ๊ก "มองเห็น" ให้อัตโนมัติ)
- **ผูกพนักงานเข้ากลุ่ม** ได้จากหน้าเดียวกัน

### โมดูลทั้งหมด

| หมวด | โมดูล |
|---|---|
| งานประจำวัน | การจอง/ผู้เข้าพัก · แม่บ้าน · งานซ่อมบำรุง |
| บริการลูกค้า | แชทลูกค้า · รูมเซอร์วิส · กิจกรรม |
| ขายหน้าร้าน | POS · บัตรกำนัล · สต๊อก |
| การเงิน & บัญชี | ใบเสร็จ/ใบกำกับ · ใบสำคัญจ่าย · รายงานบัญชี |
| ลูกค้า & การตลาด | ข้อมูลลูกค้า · สมาชิก/แต้ม · รีวิว · Affiliate |
| ผู้บริหาร | Dashboard · รายงานผู้บริหาร · Channel Manager |
| บุคคล (HR) | พนักงาน · การลา · เงินเดือน/OT · ทรัพย์สิน |
| ระบบ | ตั้งค่าระบบ · ฐานข้อมูล/ข้อมูลหลัก |

## ความปลอดภัย 2 ชั้น

1. **ซ่อนเมนู** (`Perm.CanView`) — ไม่เห็นก็ไม่กด
2. **กันเข้าหน้า** (`Perm.Guard`) — พิมพ์ URL ตรง ๆ ก็เข้าไม่ได้ เด้งกลับหน้าผู้เข้าพัก
   (ใส่ไว้แล้ว **49 หน้า**)

> เมนูจะขึ้นก็ต่อเมื่อ **ฟีเจอร์เปิด** (ดู `Feature_Flags.md`) **และ** กลุ่มสิทธิ์ให้เห็น — คนละชั้นกัน
> ฟีเจอร์ = เปิด/ปิดทั้งระบบ · กลุ่มสิทธิ์ = ใครเห็นอะไร

## เข้ากันได้กับของเดิม 100%

- **พนักงานที่ยังไม่ถูกกำหนดกลุ่ม → ใช้สิทธิ์ตามตำแหน่งเดิมเป๊ะ ๆ**
  ⟹ รัน migration แล้วระบบทำงานเหมือนเดิมทุกอย่าง จนกว่าจะเริ่มจัดกลุ่มเอง
- **Owner เข้าถึงได้ทุกส่วนเสมอ** ไม่ว่ากลุ่มจะตั้งไว้อย่างไร — กันตั้งค่าพลาดแล้วไม่มีใครเข้าหน้าตั้งค่าได้อีก
- ตอนผูกพนักงานเข้ากลุ่ม ระบบจะตั้ง `Admin.Role` ให้ตรงกับ **"ฐานตำแหน่ง"** ของกลุ่มด้วย
  เพราะยังมีหน้าเก่าอีกหลายสิบหน้าที่เช็คตำแหน่งโดยตรง (ไม่แตะผู้ใช้ที่เป็น Owner)
- ถ้าระบบสิทธิ์อ่านฐานข้อมูลไม่ได้ (ยังไม่รัน migration) → **ไม่บล็อกการทำงาน** ใช้สิทธิ์ตามตำแหน่งเดิม

## กลุ่มมาตรฐานที่ seed ให้

| กลุ่ม | ฐานตำแหน่ง | เห็นอะไร |
|---|---|---|
| เจ้าของกิจการ | Owner | ทุกส่วน |
| ผู้ดูแล / ผู้จัดการ | Admin | งานประจำวัน + ขาย + การเงิน + ลูกค้า (ไม่รวมตั้งค่า/HR/ผู้บริหาร) |
| พนักงานหน้าร้าน | Staff | งานประจำวัน + บริการลูกค้า + ขายหน้าร้าน |

ลบไม่ได้ (เป็นกลุ่มระบบ) แต่แก้สิทธิ์ได้

## วิธีใช้งานจริง

1. รัน `Database/PHASE18_Migration_23_Permission_Groups.sql`
2. Build + deploy
3. เปิด **ตั้งค่า → กลุ่มสิทธิ์ผู้ใช้** → เลือกกลุ่มมาตรฐาน หรือสร้างกลุ่มใหม่
4. ติ๊กสิทธิ์ที่ต้องการ → **บันทึกสิทธิ์**
5. เลื่อนลงไปที่ "พนักงานในกลุ่มนี้" → เลือกพนักงาน → **เพิ่ม**

มีผลภายใน 1 นาที (cache) หรือทันทีเมื่อผู้ใช้โหลดหน้าใหม่

## สำหรับนักพัฒนา

```csharp
Perm.CanView(Perm.FinReceipt)      // เห็นเมนูไหม
Perm.CanAccess(Perm.FinReceipt)    // เปิดหน้าได้ไหม
if (!Perm.Guard(this, Perm.FinReceipt)) return;   // บรรทัดแรกใน Page_Load
Perm.Invalidate();                 // ล้าง cache หลังแก้สิทธิ์
```

เพิ่มโมดูลใหม่: เพิ่ม const + แถวใน `Perm.Catalog` → เพิ่มใน seed ของ migration →
ใส่ `Perm.Guard` ในหน้าของโมดูลนั้น → ผูก `Perm.CanView` กับเมนูใน `Site.Master.cs`
